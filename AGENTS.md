# Tuition Media — Next.js 16 + React 19

## Quickstart

| Command                        | Action                                                         |
| ------------------------------ | -------------------------------------------------------------- |
| `yarn dev`                     | Start dev server at http://localhost:3000                      |
| `yarn build`                   | Production build (output to `.next/`)                          |
| `yarn start`                   | Serve production build                                         |
| `yarn lint`                    | Run ESLint                                                     |
| `yarn typecheck`               | Run `next typegen && tsc --noEmit`                             |
| `yarn format:check`            | Check Prettier formatting                                      |
| `yarn gen:api`                 | Generate `lib/api-types.ts` from `../tuition-api/openapi.json` |
| `yarn gen:api:check`           | Fail when `lib/api-types.ts` is stale                          |
| `yarn gen:site-defaults`       | Copy site content defaults and schema from the API             |
| `yarn gen:site-defaults:check` | Fail when the site content copies are stale                    |
| `yarn test:unit`               | Run vitest unit tests (`__tests__/unit/`)                      |
| `yarn test:e2e`                | Run playwright e2e tests (`__tests__/e2e/`)                    |
| `yarn test`                    | Run unit + e2e                                                 |

## Key conventions

- **Auth**: P = public, S = student, T = tutor, A = admin, SA = super admin. See `endpoints.md` for the 198 tracked schema v6 endpoints.
- **Fees and online payments**: `lib/fees.ts` (types TutorFee, TutorFeeDetail, TutorFeePayment, CheckoutQuote, CheckoutSession, PaymentAttemptView), `feeApi` (mine, get, checkout, attempt), hooks `useMyFees` (infinite), `useMyFee`, `useCheckout` (POSTs checkout then `window.location.assign(gatewayUrl)`; invalidates fees on error), `usePaymentAttempt(feeId, tranId)` (polls every 2 s for the first minute, then every 10 s, stops on a final state; refreshes the fee list, fee detail and applications when final, but never its own key), `isAttemptSettling`, `isFeeOpen`. Query keys `queryKeys.fees.all/mine/detail(id)/attempt(feeId, tranId)` (prefix ["fees"]); `invalidateFees` (fees + applications). `components/fees/fee-format.ts`: `formatMoney` (always 2 decimals, en-BD, "৳1,537.50"), `formatPercent`, `feeStatusDisplay` (Unpaid, then Overdue for DUE or PARTIAL past due, else FEE_STATUS_META), `paymentMethodText` (SSLCOMMERZ → "Online (SSLCommerz)"). Pages (TUTOR only): `/dashboard/fees` (list; BackLink "Dashboard"), `/dashboard/fees/[id]` (Summary, "Pay online" with the fee + processing charge + total breakdown and "Pay ৳X with SSLCommerz", IN_REVIEW / PAYMENTS_OFF / BELOW_MINIMUM copy, open-payment note with "Check that payment", a "Payments on hold" section for `heldPayments` (REVIEW "Being checked", UNAPPLIED "To be refunded" with the fee part; each links to its result page) placed before the promo section, Payments ledger; BackLink "Fees"), `/dashboard/fees/[id]/payment?tran=` (result page polling the attempt; one state per status; reference shown; "Try again" only while the fee is open; status icon cross-fade with motion, reduced-motion safe, aria-live; BackLink "Fee"). Application detail: the tutor's "Pay now" is now a link to `/dashboard/fees/[id]` (the disabled placeholder and "Online payment is coming soon." are gone). Tutor dashboard has a "Placement fees" card linking to `/dashboard/fees`. Admin settings: "Online payments" switch and "Processing charge" percent form (0–10) added after Commission; `NumberForm` (unit percent or days) replaces `PercentForm` and CommissionForm; `validatePercent(text, max)` in lib/admin-settings.ts (`validateCommission` = validatePercent(text, 100)); `validateDays` checks the "Refund window" form (whole days, 0–90). `NumberForm` saves with `mutateAsync().then(...)`, not a per-call `onSuccess`, so the "Setting saved" toast survives the remount that the settings refetch causes. Admin fee detail shows "SSLCommerz (online)" when the recorder is null. Admin fee writes (`invalidateAdminFees`) also invalidate the payment-attempt and refund queries. The tutor fee detail has a promo code section (see Promo codes), a "Request a refund" action on payments with refundableUntil, and a Refunds section (see Refunds). While `useCheckout().redirecting` is true, the fee detail and payment result pages show a BlockingOverlay "Taking you to SSLCommerz…".
- **Admin payments**: `lib/admin-payments.ts` has types AdminPaymentAttempt, AdminPaymentAttemptDetail, AdminPaymentSummary and AdminFeeAttempt; `adminPaymentsApi` (list, summary, get, check, review); hooks `useAdminPaymentAttempts(filters)` (infinite), `useAdminPaymentSummary`, `useAdminPaymentAttempt(tranId)`, `useCheckPaymentAttempt` and `useReviewPaymentAttempt` (writes the detail into the cache, then refreshes payment lists, fees and applications); `ATTEMPT_STATUS_META` (label, tone, hint per status); `validateNote`. Query keys `queryKeys.admin.paymentsAll`, `paymentAttempts(filters)`, `paymentSummary` and `paymentAttempt(tranId)` (prefix `["admin","payment-attempts"]`). Pages: `/dashboard/admin/payments` (`components/admin/payments-page.tsx`: summary tiles, views in `?view=`, default "Needs attention"; BackLink "Admin") and `/dashboard/admin/payments/[tranId]` (`components/admin/payment-detail-page.tsx`: amounts, fee, gateway fields, collapsed raw response, "Check with gateway" when canCheck, Approve/Reject with a note for super admins on REVIEW; BackLink "Payments"). The admin fee detail has an "Online attempts" section linking to the attempt page. Audit labels for payment.check, payment.review, promo.create and promo.update are in `lib/admin-audit.ts`.

Query keys `queryKeys.admin.promoCodesAll`, `promoCodes(filters)` and `promoCode(id)`. Pages: `/dashboard/admin/promo-codes` (`components/admin/promo-codes-page.tsx`; views active (default), off and all; super-admin "New code" dialog) and `/dashboard/admin/promo-codes/[id]` (`components/admin/promo-code-detail-page.tsx`; edit, turn off or on, redemptions; BackLink "Promo codes"). Audit labels for the five refund actions.

Pages and lib files: packages (+[id], lib/admin-packages.ts), zone-requests, applications (lib/admin-applications.ts; rows open /dashboard/applications/[id]?from=admin, which shows a read-only admin view with an "Open fee" link), fees (+[id], lib/admin-fees.ts), payments (+[tranId], lib/admin-payments.ts), promo-codes (+[id], lib/admin-promo-codes.ts), refunds (+[id], lib/admin-refunds.ts), accounts (+[id], lib/admin-accounts.ts), team (lib/admin-team.ts), subjects (lib/admin-subjects.ts), areas (lib/admin-areas.ts), settings (lib/admin-settings.ts), audit-log (lib/admin-audit.ts). The admin nav has a "Payments" item after Fees, then "Promo codes" and "Refunds". Query keys `queryKeys.admin.*` (prefix ["admin"]). Super-admin-only buttons are hidden unless isSuperAdmin. List pages use BackLink "Admin"; detail pages go back to their list. `formatAmount` in `lib/admin.ts` shows two decimals whenever there are paisa (e.g., "৳1,537.50"), whole amounts still drop decimals ("৳1,500").
- **Uploads**: `lib/files.ts` mirrors the server's limits in `FILE_RULES` (accepted types, max size, hint). `checkFile` refuses a bad file in the browser before any request. `fileContentType(file)` maps aliases (image/jpg, video/x-m4v) and falls back to the extension when the browser reports no type or application/octet-stream; `acceptFor` lists types and extensions. The PUT has a 5-minute timeout and maps R2's 403 (link expired or the file changed size) to its own message; `complete` is retried twice on a dropped connection or 5xx (it is idempotent). `useFileUpload` warns before the page unloads mid-upload and exposes `refuse(message)`; FilePicker uses it when several files are dropped. Signed media links last an hour: every `<img>`/`<video>` showing one passes `onError={useRefreshExpiredMedia()}`, which refetches active queries only when `signedUrlExpired(url)` (reads X-Amz-Date and X-Amz-Expires), so a broken file never loops. Admin Verifications and Files show the document inline through `components/files/file-preview.tsx` `FilePreview` (image, PDF in an iframe, or video; the signed link is fetched only when the admin opens the preview, because admin views of IDs are audited). `uploadFile` calls upload-url, PUTs the bytes to the signed URL through XHR (so progress and cancel work), then calls complete. `useFileUpload(purpose)` holds idle, uploading, done or error. `openFile(fileId)` opens a private file in a new tab through a signed link; the tab opens first so popup blockers allow it. `fileApi` has uploadUrl, complete, downloadUrl and remove. `components/files/file-picker.tsx` `FilePicker` uploads on pick or drop with a progress bar and cancel, shows the chosen file with Remove, reports busy through `onBusyChange` so the form holds its submit button, and calls `onPick(file)` with the picked File before it uploads (the site editor uses it for a preview). Site media uses the `SITE_IMAGE` purpose (JPG, PNG or WebP, 5 MB) and `SITE_VIDEO` (MP4 or WebM, 25 MB). Remove only clears the choice; it does not call DELETE. Wire `id` and `describedBy` from the Field render prop.

- **Performance and loading**: `next.config.ts` sets `poweredByHeader: false`; images use AVIF and WebP with `qualities` [75], trimmed `deviceSizes`/`imageSizes` and `minimumCacheTTL` 86400; `remotePatterns` come only from `NEXT_PUBLIC_MEDIA_URL_PREFIX` (https, that host and path; it must equal the API's `R2_PUBLIC_URL_PREFIX`); `optimizePackageImports` covers hugeicons, radix-ui and motion. Headers: `/assets/*` gets `public, max-age=86400, stale-while-revalidate=604800` (not immutable: the names aren't hashed), and every route gets `X-Content-Type-Options`, `Referrer-Policy` and `X-Frame-Options: SAMEORIGIN`. `canOptimizeImage(src)` in `lib/media.ts` allows only local or unsigned public-bucket URLs; signed links, `blob:` previews and other hosts stay `unoptimized`. `publicApiGet` in `lib/server-fetch.ts` never sends credentials, so use it only for data that is the same for everyone; `DISABLE_SERVER_PREFETCH=1` (set by `playwright.config.ts`) skips it. Vercel Speed Insights sits next to Analytics in `app/layout.tsx`. Geist sans is gone (Manrope is `--font-sans`); Geist Mono has `preload: false`. Above-the-fold `next/image` uses `preload`; `priority` is deprecated there. `components/footer.tsx` is a server component. `useSaveData()` (`lib/use-save-data.ts`) stops video autoplay and sets `preload="none"` on Save-Data or 2G/3G (testimonials, video card, how it works, tutor showcase). `useRefreshExpiredPageMedia()` (`lib/use-refresh-expired-page-media.ts`) calls `router.refresh()` once per page load when cached landing media has an expired signed link. The animated mesh gradient (`components/mesh-gradient/mesh-gradient-animated.tsx`) pauses its drift off screen and in hidden tabs. Profile dashboard dialogs load with `next/dynamic` on first open. Lookups (subjects, areas, education) use staleTime 30 min, gcTime 60 min and no refetch on focus. The Places autocomplete in `components/profile/address-autocomplete.tsx` debounces 250 ms and drops stale answers. `app/error.tsx` never shows `error.message`.

Route skeletons: `app/dashboard/loading.tsx`, `app/dashboard/admin/loading.tsx` (inside AdminShell), `app/onboarding/loading.tsx`, `app/tutors/[id]/loading.tsx`, `app/(site)/blog/[slug]/loading.tsx`.

## Testing quirks

- **Unit tests**: `environment: "jsdom"`, globals enabled, setup at `vitest.setup.ts`. Include pattern: `__tests__/unit/**/*.{test,spec}.{ts,tsx}`.
- **Parity snapshots**: `__tests__/unit/__snapshots__/landing-parity.test.tsx.snap` must never be updated with `-u` unless the landing design itself changes on purpose.
- **Site content tests**: `__tests__/unit/landing-parity.test.tsx`, `landing-content.test.tsx`, `site-content.test.ts`, `site-content-server.test.ts`, `site-page.test.tsx`, `site-pages-routes.test.tsx`, `admin-site-content.test.ts`, `admin-site-content-page.test.tsx`, `admin-site-content-media.test.tsx` (MediaField, with `support/upload-fake.ts` standing in for `useFileUpload`); e2e `__tests__/e2e/site-pages.spec.ts`.
- **E2E tests**: Requires dev server running. `baseURL: http://localhost:3000`. Trace: `on-first-retry`. CI doubles retry count (`retries: 2`).
- **Playwright web server**: CI uses `yarn build && yarn start`; local uses `yarn dev`. Server reused between tests when possible. The web server gets `DISABLE_SERVER_PREFETCH=1` (`playwright.config.ts`), which skips server prefetch so the browser mocks apply. A server you started yourself that Playwright reuses does not have it.
- **Blog without the API**: `publicApiGet` never throws and the unit tests (`__tests__/unit/blog-pages.test.tsx`) cover the client fallback, but under `next start` a blog slug rendered for the first time while the API is unreachable answers 500 with `app/error.tsx`: Next fails a first ISR render whose fetch failed, so nothing broken is cached. Prerendered slugs keep their last good copy.
- **Fixtures**: No fixture files. Tests use inline data or mock APIs.
- **Upload and admin unit tests**: `__tests__/unit/upload-forms.test.ts`, `admin-verifications.test.ts`, `admin-blog.test.ts`, `admin-files.test.ts`, `admin-uploads.test.ts`, `upload-flags.test.tsx`, `upload-status.test.ts`, `files.test.ts` and `file-preview.test.ts`.
- **Payment E2E specs** (mocked API, `satisfies Schemas[...]` fixtures): `__tests__/e2e/payments-tutor.spec.ts` + `payments-mocks.ts` (17 cases: fee list/detail, promo inline errors/apply/remove/100%-off waive, checkout redirect to the sandbox URL, result page PENDING→SUCCEEDED, FAILED with and without Try again, REVIEW, refund request dialog, 320px no horizontal scroll); `__tests__/e2e/payments-admin.spec.ts` + `admin-mocks.ts` (15 cases: payments queue and review approve, refund from a payment, promo create/validation/409/turn off, refunds queue approve → NEEDS_REVIEW warning → resolve, refund window setting, plain ADMIN sees no super-admin buttons, 320px).
- **Next CLI retry note**: Next 16.4.3's CLI stops the first `next dev`/`next build` run in an agent session to show an upgrade notice and lets a retry through within 5 minutes; a human terminal is not affected. CI uses `yarn build && yarn start`.

## Gotchas

- **`endpoints.md`** is gitignored but tracked locally. Updated via the `deferred` checkbox column (click `[ ]` → `[x]` in VS Code preview). Do not commit unless the gitignore changes.
- **Next.js 16 breaking changes**: APIs, conventions, and file structure may differ from older Next.js versions. Always read `node_modules/next/dist/docs/` for the resolved version.
- **Typegen + tsc**: `yarn typecheck` runs both `next typegen` and `tsc --noEmit` in that order. Run `lint -> typecheck -> test` sequentially.
- **Husky pre-commit**: Runs `yarn lint-staged` which does `eslint --fix && prettier --write`. Commit will fail if lint/format issues are auto-fixable.
- **Tailwind CSS v4**: Config moved to `postcss.config.mjs`. Do not edit `tailwind.config.*` if it exists — it may not be used.
- **Unit test mocking**: Unit tests that need the network mock `apiFetch` with `vi.mock("@/lib/api", async (orig) => ({ ...(await orig()), apiFetch: vi.fn() }))`; a full `@/lib/api` mock must spread the original because `api-client` reads `API_URL`.
- **Node version**: Local Node must match `.nvmrc` (24) in the frontend. CI uses Node 24.
